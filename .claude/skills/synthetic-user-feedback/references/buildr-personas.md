# Buildr personas

**Context:** Buildr is an invite-only beta AI app builder (describe an app, get project files and a live
preview) plus a chat assistant that makes documents. Credits are spent per reply. Four personas, all
arriving cold from a link a friend sent. Drafted 2026-11-16 from the product description; the owner has
not reviewed them.

| Persona | Goal                                        | Budget                            | Decision style                          |
| ------- | ------------------------------------------- | --------------------------------- | --------------------------------------- |
| Priya   | A website for her cafe                      | Under $20 once                    | Gut feel, wants it done today           |
| Marcus  | Prototype an internal tool, compare vendors | Company card, $20 to $100 a month | Checklist, security and trust first     |
| Dana    | Ship client work faster                     | Pays if code is hers              | Skeptical, reads the code, tests limits |
| Sam     | Turn notes into a deck or document          | Small, expensed                   | Task-driven, hates detours              |

## Priya: cafe owner, not technical

- 38, runs one cafe, uses Instagram and Canva, has never written code.
- Wants a site with menu, hours and address. Has been quoted $1,500 by an agency.
- Trusts what looks professional and simple. Abandons anything that feels like a developer tool.
- Skims. Gives a page about 10 seconds before deciding if it is for her.

**Key questions:** "Is this for people like me?" "Do I need to know code?" "What does it cost, really?" "Can I get my own web address?"

**Red flags:** jargon (files, tokens, repository), blank screens with no guidance, surprise costs.

**What gets her to convert:** a result she can see in a minute, plain prices, a way to publish it.

## Marcus: product manager at a 200-person company

- 34, wants a quick internal dashboard prototype to show his boss; has tried Lovable and Bolt.
- Compares on pricing, speed, export, security, team features.
- Reads the pricing page and the privacy page before putting anything company-related in.

**Key questions:** "Where does my data go?" "Can my team share projects?" "Can I export to GitHub?" "How does this compare with Lovable?"

**Red flags:** no company name or contact, draft legal pages, no social proof, features that say "planned".

**What gets him to convert:** clear data handling, GitHub or deploy, a result good enough to demo.

## Dana: freelance developer

- 29, builds client sites, wants speed on boilerplate, will not ship code she cannot own.
- Opens the code view first, tries to break things, notices cheap tricks.
- Judges quality of generated code and whether she can take it elsewhere.

**Key questions:** "Can I download it?" "Is the code real React or a toy?" "What model is this?" "What happens when I run out of credits?"

**Red flags:** lock-in, opaque pricing, a preview that is not the real app, slow or flaky generation.

**What gets her to convert:** clean code, ZIP or Git export, honest limits.

## Sam: operations analyst

- 31, needs a deck and a summary document from rough notes, weekly.
- Uses the chat assistant, not the builder. Wants a download in Word or PowerPoint.
- Patience: two attempts, then back to the old way.

**Key questions:** "Can it make a PowerPoint?" "Will it use my notes?" "Is it free?"

**Red flags:** being sent to a builder when she wanted a document, empty states, errors without next steps.

**What gets her to convert:** one request in, one file out, that looks presentable.
