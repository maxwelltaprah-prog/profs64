# Assumptions

Decisions made where the brief was silent or ambiguous. Change them here first.

## Milestone 0

- **Project location.** The app lives in `buildr/`, a subfolder of the session's working directory. The parent is a home directory holding SSH keys and session tokens, so making it the repo root would put those under git and the secret scanner.
- **Next.js 16.** `create-next-app` installed Next 16.4.5, where `middleware.ts` is now `proxy.ts`. All "middleware" requirements are implemented in `proxy.ts`. I read the bundled docs in `node_modules/next/dist/docs/` rather than relying on memory.
- **Cache Components off.** The scaffold enabled `cacheComponents`. Nonce-based CSP needs per-request rendering, so it is disabled.
- **ESLint 9 and TypeScript 5.9.** ESLint 10 and TypeScript 7 exist, but `eslint-plugin-import` and the typescript-eslint stack target ESLint 9 and TS 5. Staying on the supported combination.
- **Exact pins.** `.npmrc` sets `save-exact=true`; every dependency uses an exact version, enforced by a unit test.
- **Secret scanning.** gitleaks runs in CI through its GitHub Action and locally through `scripts/secret-scan.sh`. The pre-built binary could not be downloaded in this environment, so it was built with `go install github.com/zricethezav/gitleaks/v8@latest` into `~/.local/bin`. The hook fails if gitleaks is missing rather than skipping silently.
- **Subagents.** Defined in `.claude/agents/`. No `docs/REVIEW_*.md` fallback files were created; see the note below on how reviews ran in the creating session.
- **Playwright e2e** starts the production build with `AI_MODEL_MODE=fake`. The fake model arrives in Milestone 3.
- **Rate limiting.** Upstash is used when its env vars are set; otherwise an in-memory limiter is used. The in-memory limiter is per-process and is documented as not suitable for multi-instance production.
- **Auth throttling.** Auth rate limits are applied to the app's own auth route handlers. Supabase's hosted limits are an additional layer, not a replacement.
- **Reviewer subagents in this session.** The four agents are defined in `.claude/agents/`, but they were not registered in the session that created them, so the milestone reviews were done manually against the same checklists. They load in later sessions.
- **No Docker daemon here.** `supabase start` cannot run in this environment (no Docker socket). Postgres 16 server binaries are installed locally, so Milestone 1 integration tests run against a local Postgres 16 with a minimal shim of Supabase's `auth` schema and roles. CI runs the same tests against real local Supabase. The shim is not identical to Supabase; results here are reported as such.
- **Session cookies are httpOnly.** All data access goes through server code, so the browser never needs to read the Supabase session; cookie options are forced to `httpOnly`, `sameSite=lax` and `secure` in production.
- **Optional env vars.** `APP_URL` (public base URL for auth emails) and `LOG_LEVEL` are optional additions to the brief's variable list. Production should set `APP_URL`; a request Host header is attacker-influenced, so it is only used as a development fallback.
- **Password policy.** Length-first (12 to 128 characters), rejects passwords containing the email local part or on a short deny-list, and checks Have I Been Pwned by k-anonymity (only a 5-character SHA-1 prefix leaves the server). If that service is unreachable the check fails open and logs a warning.
- **Failed-login lockout is per account, not per source.** Five failures per 10 minutes for an email address block further attempts from anywhere, which stops distributed guessing but lets an attacker temporarily lock out a known address. This is the usual trade-off; the lockout expires on its own.
- **Assistant messages are server-written.** Users may insert only `user` messages through RLS; assistant messages go through a narrow service-role function (Milestone 3) so the API cannot forge model output.
- **Credit clamp.** A deduction larger than the remaining balance is clamped to the balance (never negative) and the shortfall is returned and logged.
- **shadcn/ui is not used (stack conflict, decided in favour of the security requirement).** The brief asks for shadcn/ui and also for a strict CSP with nonces. shadcn's dependencies (Radix positioning, `react-resizable-panels`, `cmdk`, `sonner`) emit inline `style` attributes or runtime `<style>` tags, which that CSP blocks. Allowing `unsafe-inline` for styles would weaken the policy. The UI primitives (`components/ui/*`, split pane, command palette, tree) are hand-built with the same conventions (variants, `cn`, semantic tokens) and no inline styles.
- **Next.js 16 `proxy.ts`** is the replacement for `middleware.ts`; the brief's "middleware" is implemented there.
- **Split pane size** is written to a CSS variable through the CSSOM (allowed by CSP) and remembered per user and project in `localStorage`. Below the `md` breakpoint the panes stack.
- **Workspace layout.** Chat on the left; the right side has Code (file tree plus read-only viewer) and Preview tabs, where Preview is the "coming next" placeholder.
- **Chat UI ordering.** The chat panel in Milestone 2 shows persisted messages with a composer that is inert; streaming, tool lines, Stop and Cmd+Enter are built with the chat route in Milestone 3 because they depend on it.
- **Input border token.** `--input-border` is a separate, darker token so form controls meet the 3:1 non-text contrast requirement.
- **E2E environment.** Playwright starts the app with placeholder Supabase values pointing at a closed local port. Signed-out pages render normally; real auth round trips are not covered by e2e here (KI-7).
- **Project creation is two statements** (project, then starter files) because PostgREST has no multi-statement transaction. If seeding fails the empty project is deleted again.
- **Default model and prices.** `z-ai/glm-5.2` was confirmed to exist on OpenRouter. The brief's $1.40 in and $4.40 out per million tokens match its list price; OpenRouter currently shows a 70% promotional discount (about $0.42 and $1.32), so the app charges slightly more than it costs. Prices live in `lib/ai/models.ts`.
- **Fallback model.** `deepseek/deepseek-v3.2` (confirmed on OpenRouter, supports tool calling). Its prices in `models.ts` ($0.29 in, $0.43 out) are the discounted figures grossed up by an estimate and are not verified list prices; check them before relying on the fallback. It is used only when the default fails before returning a stream, and the model that answered is the one billed.
- **Billing rules.** 1 credit = $0.03, rounded up to two decimals, minimum 0.1 per request that reached the model. A request that fails before the model produces anything is not billed. Stop and disconnects are billed for tokens used, with the cut-off step estimated at 3 characters per token (over-counts). If the provider reports no usage, the whole request is estimated and a warning is logged.
- **Spend limits.** Rolling daily cap per account (default 50 credits, `AI_DAILY_CREDIT_CAP`), 20 chat requests per user and 60 per IP per 10 minutes, 12 tool steps, 6,000 output tokens per step, 120 second request timeout, 60 KB of file contents per request, last 20 messages replayed. `AI_DISABLED=true` is the global kill switch.
- **Context layout.** The system prompt holds only instructions. The file list and file contents go in a first user message wrapped in a random per-request boundary and labelled untrusted, so file text is never placed in the system prompt.
- **History comes from the database.** The client sends only its newest message and project id; earlier turns are loaded server-side, so a client cannot forge history. Stored assistant turns drop reasoning text and unfinished tool calls and replace file contents in tool results with a stub.
- **Fake model.** `AI_MODEL_MODE=fake` uses a scripted model. It is refused when `OPENROUTER_API_KEY` is set in production.
- **Live file tree.** After each file-changing tool call the client refetches the project's files from the server (coalesced), and the header balance refreshes when the turn ends.
- **One live response per account** (per server instance) and a billing retry without the project reference if the project is deleted mid-request, so neither parallel requests nor deleting the project can make usage free.
- **Prompt-first landing.** The home page asks for the app description before an account. The description is stored in the browser (localStorage, not the database) until sign-in, because there is no user to attach it to yet; the project name is the prompt's first line, cut at 60 characters. A signed-in person who types a prompt on the home page gets a new project each time.
- **Lovable's package.json.** The owner supplied Lovable's `vite_react_shadcn_ts` package.json and asked to "use the same tech stack". It is the template Lovable scaffolds for generated projects, so it was applied to Buildr's starter template and preview, not to Buildr's own UI (which stays on Next.js with the nonce CSP that excludes shadcn/ui, per Milestone 0). A subset of its dependencies is included: the ones the starter's five components and router need. The rest (forms, charts, carousels, date pickers, drag and drop, PDF) can be added by the model per project.
- **"Auto suggestions" means follow-up chips** under the chat box, computed locally from the project's files and conversation, not model-generated and not free-text autocomplete. Revisit if autocomplete was meant.
- **"Share" means the device share sheet, else copy to clipboard.** No public link is created: that would need a new table and a decision about who can read a reply.
- **"Attach" means text files** (code, markdown, CSV as text, JSON, etc.). Images and PDFs are not supported because vision support of the default model was not verified.
- **No database migration for this feature set.** Credits per reply live in the stored reply's parts, ratings in the existing audit log, attachments as project files.
- **"Voice note" is dictation** into the message box through the browser's speech recognition, not an audio file sent to the model.
- **Login and "get started" restyle.** The attached screenshot is another product's login page. Its layout ideas were used (centered column, provider buttons, OR divider, large controls, "Last used" marker); its logo, gradient and brand artwork were not, and the colours stay within CLAUDE.md (neutral plus one accent). "Get started" was read as the sign-up page and the post-sign-in project-creation screen (`/start`).
- **Email and password stays the sign-in method.** The reference is email-first with providers. Switching to email codes or magic links would change the auth flow and needs a Supabase decision, so it was not done. Provider buttons exist but are hidden until `OAUTH_PROVIDERS` is set, so nothing broken is ever shown. Buttons are text only (no third-party logos).
- **Ponytail** is installed as skills only (`ponytail`, `-review`, `-audit`, `-help`, `-debt`, `-gain`). Its session hooks, status line and "band" importer were not installed: they run scripts on every prompt and read past sessions. Its rule (smallest change that fully works, with a test for risky logic) matches "prefer boring, proven solutions" and is applied to new work.
- **ui-ux-pro-max** is installed as one skill with its local search data (no network use; checked the scripts). Its generated design system for this product suggested a green accent and a glow; CLAUDE.md wins (see KI-28), so only its accessibility and form rules were used: visible labels, focus moves to the invalid field, show/hide password, paste and password managers allowed.
- **Sign-in design from the owner's screenshots** (two other products' sign-in pages). The split layout, provider buttons, OR divider, placeholders and centred title were followed. Their logos, illustrations, photos, CAPTCHA widget and cookie banner were not: the right panel is an original illustration of Buildr itself (an invented barbershop page), and no third-party CAPTCHA or tracking was added.
- **"A bit glassy"** was taken as subtle glass (translucent surface plus backdrop blur) on sticky bars, dialogs, the command palette and the sign-in showcase, chosen by the owner over glass everywhere. CLAUDE.md was updated; no glows or colourful gradients.
- **Replit as a reference** (owner's screenshots of its home and workspace). The layout pattern was followed: left rail, greeting with the prompt box, recent projects, idea cards, and the "get notified when done" prompt. Its branding and colours were not copied. The signed-in rail adds Settings and an Upgrade link; paid plans and credit top-ups are not available, so Upgrade reports the real plan and balance instead of offering a fake checkout. Settings covers appearance, password recovery, account/data management and keyboard shortcuts. The workspace keeps its own layout (no rail) for now.
- **Chat agent scope.** "Like ChatGPT/Claude" was read as a general assistant with history and document creation (PowerPoint, Word, PDF). No web browsing, file uploads or image generation in this version.
- **Free fallback rules.** "Free model for an extra 24 hours when they run out of credit for the day" was read as: out of credits means a balance under 1 credit or the daily cap reached; the free window lasts 24 hours from the first message after that; a new window can start only 24 hours after the previous one ended. Chat agent only, per the owner. Free replies are capped at 40 per person per day because OpenRouter's free quota is shared by all users (50 requests a day in total without purchased credits).
