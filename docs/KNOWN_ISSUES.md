# Known issues

Medium and low findings that are not fixed yet, with the reason.

| ID    | Finding                                                                                                                                                                                                                                                                                                                                                                                                                              | Severity | Rationale                                                                                                                                                                                                            | Status          |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| KI-1  | `npm audit` reports moderate advisories in `minimatch` through the typescript-eslint chain pulled in by `eslint-config-next`.                                                                                                                                                                                                                                                                                                        | Medium   | Dev-time lint tooling only; not in the runtime bundle. The audit gate is set to `high`. Upstream fix needed.                                                                                                         | Open            |
| KI-2  | GitHub Action versions are pinned to major tags, not commit SHAs. Verified against current releases: `actions/checkout@v6`, `actions/setup-node@v7`, `github/codeql-action@v4`. Not verified (no access to their release pages): `supabase/setup-cli@v1`, `gitleaks/gitleaks-action@v2`, `google/osv-scanner-action@v2`.                                                                                                             | Medium   | The workflows have never run (no GitHub remote yet), so the unverified pins and the `supabase status -o env` key mapping in the integration job may need correction on first run. Pin to SHAs once a remote exists.  | Open            |
| KI-3  | CI does not upload the Playwright report on failure.                                                                                                                                                                                                                                                                                                                                                                                 | Low      | The `upload-artifact` version could not be verified, so the step was left out rather than guessed.                                                                                                                   | Open            |
| KI-4  | `supabase/config.toml` was written by hand; the Supabase CLI cannot run here (no Docker).                                                                                                                                                                                                                                                                                                                                            | Medium   | Key names follow the documented schema but `supabase start` has not validated it, nor the CI integration job's env mapping. First CI run is the check.                                                               | Open            |
| KI-5  | Credit deduction happens after the stream ends, so concurrent chats can each pass the pre-check and together spend past the balance. The DB clamps the balance at zero (never negative) but the overshoot is not billed.                                                                                                                                                                                                             | Medium   | Bounded by the per-user daily spend cap, per-request token limit and rate limits added in Milestone 3. A reservation scheme would remove it; deferred as out of scope for this phase.                                | Open            |
| KI-6  | Auth rate limits default to a per-process in-memory limiter.                                                                                                                                                                                                                                                                                                                                                                         | Medium   | Correct for one instance only. Set the Upstash variables for multi-instance deployments; the limiter falls back to memory and logs a warning if Redis is down.                                                       | Open            |
| KI-7  | Verified on 2026-11-07 against a real Supabase project: login, wrong-password response, session cookies, protected pages, export and deletion. NOT verified: the emailed confirmation link, the reset-password email flow, and that "Confirm email" is enforced by the project (the test user was created through the admin API, which bypasses it).                                                                                 | Medium   | Sign up with a real inbox and walk the confirmation and reset links once; check the Supabase dashboard setting.                                                                                                      | Partly verified |
| KI-8  | When no client IP header is present (no trusted proxy, e.g. local `next start`), every caller shares one `unknown` rate-limit bucket.                                                                                                                                                                                                                                                                                                | Low      | Production runs behind a proxy that sets `x-real-ip`/`x-forwarded-for`. If deployed without one, the IP-keyed limits become a shared global limit and the headers are spoofable; see docs/SECURITY.md (Milestone 5). | Open            |
| KI-9  | `POST /api/auth/reset-password` accepts any signed-in session, not only a recovery session, so a hijacked session could change the password without knowing the old one.                                                                                                                                                                                                                                                             | Medium   | Supabase's `secure_password_change = true` (set in `supabase/config.toml`) requires a recent sign-in, but that setting is unverified here (KI-4). Add an explicit recent-auth or old-password check before launch.   | Open            |
| KI-10 | The in-memory limiter evicts the oldest key once 10,000 distinct keys are tracked, so a flood of fake emails could reset a victim's lockout counter.                                                                                                                                                                                                                                                                                 | Low      | Memory mode only; Upstash limiter is not affected. Use Upstash in any multi-user deployment.                                                                                                                         | Open            |
| KI-11 | Signup and forgot-password return identical bodies and statuses for existing and new addresses, but response timing may differ.                                                                                                                                                                                                                                                                                                      | Low      | Timing differences are small next to network jitter and mail latency; a queue-based send would remove them.                                                                                                          | Open            |
| KI-12 | Row caps (50 projects per user, 2,000 messages per project, 100 files per project) surface as a database check violation. Translated to plain messages in `translateDbError` (Milestones 2 and 3); the chat route tests cover the mapping, not each trigger end to end.                                                                                                                                                              | Low      | The workspace UI in Milestone 2 and the chat route in Milestone 3 must translate these into plain messages.                                                                                                          | Open            |
| KI-13 | Verified on 2026-11-07 against real Supabase: project creation with starter files, file listing, chat file writes, message persistence, and the 404 for another user's project all worked through PostgREST.                                                                                                                                                                                                                         | Low      | Covered by the manual run (scripts not kept in the repo); add them as a CI e2e against local Supabase.                                                                                                               | Mostly resolved |
| KI-14 | The command palette "Change theme" action updates the page theme but not the state of the header toggle icon until the next navigation.                                                                                                                                                                                                                                                                                              | Low      | Cosmetic. Lift theme state into a shared context.                                                                                                                                                                    | Open            |
| KI-15 | Dashboard and workspace pages, the split pane drag behaviour and the palette have no browser test while signed in, because signing in needs a real Supabase. Keyboard resizing and the palette are covered by jsdom tests only.                                                                                                                                                                                                      | Medium   | Add a signed-in Playwright flow in CI against local Supabase.                                                                                                                                                        | Open            |
| KI-16 | Below the `md` breakpoint the chat and the code view stack at equal height with no tab switcher, so each is short on a phone.                                                                                                                                                                                                                                                                                                        | Low      | Layout works and nothing overflows; a Chat / Files / Preview tab bar for small screens is the better design.                                                                                                         | Open            |
| KI-17 | Verified on 2026-11-07: a real chat request on the live stack streamed, wrote files, stored messages and charged 0.28 credits for 4,324 input and 501 output tokens with a matching ledger row. A Stop mid-stream was billed 0.13 credits using an input estimate (no output counted yet). Not yet compared against OpenRouter's activity page. OpenRouter reports cached input tokens, which the app bills at the full input price. | Low      | Compare the two ledger rows with OpenRouter's activity page.                                                                                                                                                         | Mostly resolved |
| KI-18 | Billing happens after the stream, so one request can cost more than the balance. The one-response-at-a-time lease is per server instance, so several instances can still overlap. The ledger clamps the charge to the balance and records the shortfall (KI-5). With a 6,000-token output cap and 12 steps the worst case is a few credits.                                                                                          | Medium   | Bounded by the per-step cap, step cap, timeout and daily cap.                                                                                                                                                        | Open            |
| KI-19 | A tool call that writes a file is not rolled back if the same request is later stopped or fails; partial work stays in the project.                                                                                                                                                                                                                                                                                                  | Low      | By design: each file write is complete on its own and the person sees it in the file tree.                                                                                                                           | Open            |
